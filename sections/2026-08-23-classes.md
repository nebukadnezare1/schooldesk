# Section Classes — 23 août 2026

## Contexte

Deuxième section traitée dans la revue section par section (après Élèves), à la demande directe de l'utilisateur : « on fait la même chose pour classes, personnel ». Même traitement que la section Élèves appliqué à Classes.

## État de départ

Liste de cartes simples (nom, niveau, capacité), formulaire minimal en bas de page (nom, niveau, capacité), pas de professeur/assistant assignable depuis l'interface, pas de statut visible, pas de modification, pas de suppression, pas de tri, pas d'effectif ni de taux de remplissage.

## Changements apportés

### Backend (`apps/backend/src/academic-routes.ts`)

- `GET /api/classes` : calcule et renvoie maintenant, pour chaque classe, l'effectif (`studentCount`), la répartition filles/garçons (`girls`/`boys`) et le taux de remplissage (`fillRate`), à partir des inscriptions actives. Inclut aussi le professeur et l'assistant (id, prénom, nom).
- `POST /api/classes` : accepte désormais `teacherId` et `assistantId`.
- `PATCH /api/classes/:id` (nouveau) : modification complète (nom, niveau, salle, capacité, professeur, assistant, statut).
- `DELETE /api/classes/:id` (nouveau) : **désactive** la classe (statut `INACTIVE`) au lieu de la supprimer — cohérent avec le principe de ne pas perdre l'historique (`SchoolClassStatus` n'a que `ACTIVE`/`INACTIVE`, pas de suppression physique).

### Frontend

- Fenêtre modale complète (`+ Nouvelle classe`) : nom, niveau, salle, capacité, professeur (liste du personnel), assistant, statut (en édition uniquement).
- Tableau triable : Nom, Niveau, Salle, Professeur, Assistant, Filles/Garçons (avec effectif/capacité), Remplissage (%), Statut.
- Menu contextuel au clic droit sur une ligne : Modifier / Supprimer.
- Les classes désactivées disparaissent de la liste et de tous les sélecteurs de classe ailleurs dans l'application (Présences, formulaire élève), mais restent en base.

## Fichiers modifiés

- Backend : `apps/backend/src/academic-routes.ts`.
- Frontend : `apps/frontend/src/pages.tsx` (page Classes), `apps/frontend/src/App.tsx` (état, sauvegarde, filtrage des classes inactives), `apps/frontend/src/types.ts` (type `SchoolClass` enrichi).

## Tests effectués

Testés en navigateur réel via Playwright :

- Création d'une classe avec professeur assigné → visible dans le tableau avec les bonnes informations.
- Modification de la capacité via le menu contextuel → mise à jour visible immédiatement.
- Désactivation via le menu contextuel → disparaît du tableau Classes et du sélecteur de classe de la page Présences.
- Navigation complète de l'application après chaque étape : aucune erreur console, aucune régression.

## Écarts connus restants

- Pas de gestion explicite multi-année scolaire pour créer une classe dans une année différente de l'année active (le formulaire crée toujours dans l'année active).
- Le taux de présence par classe (mentionné section 13 du cahier des charges) n'est pas encore affiché ici (disponible en partie sur le Dashboard).
